регистрации и входа. Прочитаны отрисованные DOM поиска и карточек; проверены

Ставки, загрузка CSV, регистрация и Telegram-публикация не выполнялись.

Это ограниченная исследовательская проверка, **не smoke встроенного Chromium
SearchCar**. Windows, headless-режим, повторный запуск с чистым профилем,
лимиты частоты запросов и работа установленного приложения не проверены.
Невозможность web-инструмента прочитать IAA не оказалась блокировкой сайта:
в браузере обе выдачи и карточки открылись.

Исходные URL сохранены в [очищенных наблюдениях](fixtures/msa01/public-observations.json).

бесплатный автомобиль. Пробег `0 NOT ACTUAL` / `1 Inoperable Digital Dash`
не должен отображаться как достоверный почти новый автомобиль.

Конкретный пример IAA: ссылка `/VehicleDetail/46628754~US`, Stock # `46129034`.
Видимые `$18,065 USD` подтверждены в карточке как **Actual Cash Value**, не bid.

версии USA его нужно явно исключать с указанием рыночного охвата, не объявлять
ошибкой/продажей и не считать USD. VIN для дедупликации непригоден: он скрыт.

## Расписание и локаль

- Copart 65507986: `Tue. Oct 06, 2026 04:00 PM GMT+2` → в этом наблюдении
  `2026-10-06T14:00:00Z`. Отрисованный offset известен; IANA-пояс площадки из
  этого текста **не установлен**. Нельзя повторно интерпретировать 16:00 как
  местное время Детройта. Countdown — вспомогательный, не основной источник.
- IAA 46628754: `Tue Oct 6, 8:30am (CDT)`; год подтверждён ссылкой списка продажи
  `/SalesList/613~US/10062026`. Для этого дня CDT означает UTC−05:00, то есть
  `2026-10-06T13:30:00Z`. Часовая настройка сайта показывала CDT, хотя компьютер
  находится в Europe/Warsaw. Нельзя считать время IAA временем компьютера.
  Для других дат/аббревиатур нужны отдельные fixtures и DST-проверки, не
  постоянное вычитание пяти часов.
- Есть реальные строки без назначенных торгов: Copart `Upcoming lot`, IAA
  `Auction Not Assigned`. Они не должны попадать в «Сегодня» по догадке.
- Время старта относится к аукциону; lane/item не дают точного времени выхода
  машины. Истечение даты не подтверждает продажу или завершение торгов.
- Штатным меню Copart проверен переход English → Русский → English карточки
  65507986: URL получил `/ru/lot/…`, затем вернулся к `/lot/…`; ID сохранился,
  рынок оставался USA. Название автомобиля осталось английским. Это не перевод
  содержимого сторонним сервисом. **Полный цикл русской поисковой ссылки с
  сохранением всех фильтров ещё не проверен**; нельзя объявлять его готовым.

## Выбор способа и незакрытые проверки

Технический **кандидат** для обоих сайтов — чтение отрисованных публичных страниц
в браузере. Он показал необходимые сведения в исследовательской сессии, но

### Контракт времени для реализации

1. Сохранять исходную дату/пояс, точность и момент наблюдения вместе с UTC instant.
   Не выводить пояс из местоположения площадки: IAA в этой сессии отображает
   CDT и для Long Island/Jacksonville. Copart отображает CEST и для Detroit.
2. Читать реальный пояс компьютера при расчёте/отображении, не фиксировать Warsaw
   и не считать постоянную разницу между Европой и США. Распознавать AM/PM,
   американский формат даты и контекстные часовые сокращения. Незнакомый или
   неоднозначный пояс — неизвестное время, а не догадка.
3. «Сегодня» = UTC-интервал от локальной полуночи до следующей локальной
   полуночи, либо равенство локальных календарных дат. Не следующие 24 часа.
   Длина локального дня может быть 23/25 часов.
4. Остаток = `auction_start_utc - now_utc`; обновлять в UI без запроса к сайту.
   Подпись: «До начала аукциона — 4 ч 15 мин», рядом локальные дата/время.
   Последняя проверка расписания должна быть видна: сайт может перенести торги.
5. При прошедшем времени показывать «Время начала аукциона прошло», если нет
   подтверждённого живого статуса. Не объявлять машину проданной, доступной для
   покупки или текущие торги активными только на основании часов.
6. Лоты без даты не включать в «Аукционы сегодня»; не удалять их из наблюдения.
   Лоты с началом сегодня, уже прошедшим, оставлять в дневной выборке с пометкой
   согласно прежнему решению пользователя; отдельный фильтр «Предстоящие»
   возможен, но не принят вместо этого правила.
7. Расписание относится к началу аукциона/сессии. Lane/Run#/Item# не позволяют
   обещать точное время выхода конкретного автомобиля.

### Сравнение решений

| Решение | Что сохраняем | Ограничения | Решение для SearchCar |
| --- | --- | --- | --- |
| Штатная Share/Search-ссылка IAA | Выданную сайтом ссылку | Нужно найти и проверить без аккаунта, в чистой сессии и после перезапуска | Использовать, только если весь цикл подтверждён; не обязательный ввод |
| Отдельный browser profile/storage snapshot на проект | Часть состояния сайта | Секреты, объём профилей, истечение сессии; sessionStorage/JS-память не гарантированы | Вспомогательное состояние, не источник истины |
| Захват поискового пресета в окне SearchCar | Публичные условия + версия формата + сводка | Нужны реальные имена/идентификаторы и проверяемое восстановление IAA | Рекомендуемый UX: не заставляет дублировать все поля сайта |
| Собственная форма условий в SearchCar | Поддерживаемые фильтры проекта | Справочники, зависимости make/model, AND/OR и новые фильтры требуют поддержки | Контролируемый fallback/следующий этап, не обещание всех фильтров сразу |

Полный export браузерного state не следует класть в проект или backup как
«фильтры»: он может содержать данные доступа. Обычный Playwright storage state
сохраняет cookies/localStorage и опционально IndexedDB, но sessionStorage требует
отдельной обработки. Это ограничение транспорта, не найденный механизм IAA.
См. [Playwright authentication/storage](https://playwright.dev/python/docs/auth#session-storage),
[storage_state](https://playwright.dev/python/docs/api/class-browsercontext#browser-context-storage-state),
[MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage).

### Рекомендуемый сценарий и границы

1. «Настроить поиск IAA» открывает принадлежащее SearchCar окно. Пользователь
   применяет условия и подтверждает «Использовать этот поиск». Исследование
   сначала наблюдает обычные действия сайта, не вызывает скрытый API отдельно.
2. Adapter извлекает именно конфигурацию выполненного поиска: значения,
   группировки/диапазоны и исключения. Видимые чипы служат дополнительной
   проверкой, не полным query: быстрые featured-переключатели и скрытые группы
   тоже должны учитываться. Unknown/неподдержанные условия нельзя отбрасывать.
3. В проекте сохраняется версия `search_config`: source, entry_url, публичные
   criteria, краткая сводка, revision/hash и время проверки. Здесь нет cookies,
   CSRF, токенов, CAPTCHA state или всего localStorage. Одинаковый entry_url
   может принадлежать разным конфигурациям — текущую уникальность search_url
   потребуется пересмотреть с миграционными тестами, а не добавлять fake query.
4. Перед каждым обновлением adapter восстанавливает сохранённые значения через
   обычные элементы сайта. Восстановление allowlisted search-storage/нативного
   формата допустимо только после live-доказательства, что этот формат является
   публичными условиями, переносится и не связан с доступом. Не угадываем параметры
   и не переносим challenge cookies. Прямой private endpoint не является fallback.
5. Перед чтением и при пагинации сверяются фактические применённые условия с
   frozen revision/hash запуска. Не сравниваем постоянное число результатов:
   инвентарь меняется. Одни совпавшие названия машин также не доказывают фильтры.
6. Потеря условий → «Не удалось восстановить фильтры»/partial, без перехода на
   общую выдачу, исключения прежних машин и Telegram. Изменённый пользователем
   во время CAPTCHA поиск не принимается за прежний проект.
7. Общая очередь и имеющийся профиль источника остаются. Перед A/B/A явно
   применяется профиль поиска нужного проекта; нельзя полагаться на последнюю
   активную вкладку или запускать два Chrome с одним user-data-dir. Согласия
   остаются состоянием собственного браузера, а публичные пресеты — данными проекта.

URL и browser state — разные части. Для Encar/Copart существующий режим URL
сохраняется, если он воспроизводит условия; новые сайты могут дать свой capture/
restore в модуле. Это не универсальный recorder мыши и не runtime plugin system.
Нельзя сохранять произвольный JS-код в конфигурации или воспроизводить его из БД.

### Восстановление IAA: проверка и реализация 16–17.10.2026

Предыдущее ограничение `creation_url=null` заменено проверенным source-test
путём. У IAA обнаружен штатный `RequestUri` внутри `ResultHeaderContainer`:
он меняется после обычного поиска, хотя адресная строка остаётся `/Search`.
Это собственная ссылка сайта, не придуманные параметры и не отдельный API.
Публичный [SearchPage.js](https://www.iaai.com/prod/js/SearchPage.js) подтверждает
нативные элементы сортировки/размера страницы; их реальные обработчики проверены
в принадлежащем исследованию браузере, не в личном профиле пользователя.

Живые наблюдения:

- В чистом search-state ссылка восстановила `CADILLAC`, `SUVs`, `ESCALADE`,
  `Run & Drive`, `Year=2017–2027`. Затем проверено A → закрытие → B (`BMW`) → A
  со сравнением публичных полей фактически отправленного штатного запроса.
- Одна ссылка недостаточна: при открытии менялась сортировка. Открытие общей
  `/Search` также могло сохранить предыдущую подборку. Поэтому не используем её
  как fallback и не переносим весь localStorage.
- Штатная ссылка может включать курсор: ссылка с третьей страницы и размер100
  приводила к отсутствию активного номера/пустому фрагменту при total82.
  Прежде чтения необходим обычный переход на первую страницу, затем применение
  сохранённой сортировки и размера. Это не повод ослабить full-readiness.
- Реализованный collector после этого прошёл **4 страницы / 82 лота**:
  25+25+25+7, complete=true. Это чтение публичного списка, не запись82 машин
  в рабочую БД: лоты без подтверждённой даты по-прежнему не создаются.

Сохраняются только versioned criteria, summary, hash, время захвата и native
creation URL. При каждом повторе и странице проверяются фактические условия,
сортировка, page size/cursor и успешный ответ. Изменение total не используется
как доказательство фильтров; оно остаётся отдельной проверкой полноты обхода.
Допустимы только подтверждённые нормализации порядка групп/analytics metadata,
пустого FullSearch и штатного baseline `Default=True`; остальные значения не
отбрасываются. Код не вызывает private endpoint отдельно и не меняет JS-модель
сайта: используются штатная ссылка и handlers существующих контролов.

Это ограниченная live-проверка выбранных комбинаций, **не** гарантия всех
фильтров IAA/доступа с любого устройства. Если native URI потеряет условие,
не сохранит ZIP/статус/рекомендации либо не найдётся нужный sort control, поиск
завершится ошибкой без общего поиска, удаления прежних лотов и Telegram.
Восстановление сложной multi-sort/geo-конфигурации, если URI её не сохраняет,
пока не реализовано; для него нужен отдельный подтверждённый UI-путь.
CAPTCHA не проходится автоматически,429 останавливает обращения.

`native-uri-proof.json`, `uri-roundtrip.json`, `live-collector.json` и TDD XML.
