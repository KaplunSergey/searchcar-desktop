# Аукционные источники и подборка в Telegram

Дата: 5 октября 2026 года. Статус: план для обсуждения, код не реализован.
Дополняет [архитектуру источников](MULTISOURCE_ARCHITECTURE_PLAN.md).

## 1. Согласованный сценарий

- Источники двух типов: площадки объявлений (Encar) и аукционы (Copart, IAA).
- Каждый сайт — отдельный встроенный модуль, поставляемый с релизом приложения.
  «Источник» означает сайт; «проект» означает сохранённую поисковую подборку.
  Например, `Audi A5 — Copart` и `Audi A5 — IAA` — два проекта разных источников.
- Один сайт на проект; объединение сайтов внутри одного проекта пока исключено.
- Пользователь вставляет ссылку на поисковую выдачу и даёт проекту название.
  Добавление единичного лота по прямой ссылке — отдельная дополнительная функция.
- Первое исследование охватывает сайты Copart USA и IAA USA из примеров пользователя.
  Канадские/европейские сайты не считаются поддержанными автоматически.
- Аккаунтов нет: сначала исследуем доступные публичные сведения без входа.
  Поддержку входа/официальных файлов не включаем в первый согласованный сценарий.
- Ключевые данные — автомобиль, прямая ссылка и дата/время аукциона.
- Уточнение 09.10.2026: нужна копия главного изображения автомобиля, а не
  только внешний адрес. Подтверждён скриншот области главного изображения
  из выдачи, не скачивание исходного фото. Подготовка хранения и проверки — MSA-05; разрешённый канал данных
  и права публикации фото — MSA-01. Автоматическое открытие карточек/галерея
  этим уточнением не включаются.
- Запуски сайтов/проектов выполняются через общую последовательную очередь:
  один проект за раз. Одновременная постановка нескольких сайтов не означает
  параллельное обращение к ним (подтверждено 09.10.2026; реализация MSA-06).
- «Сегодня» определяется по текущему часовому поясу компьютера.
- Telegram-подборка отправляется **после поиска**, без отдельного ежедневного
  таймера публикаций. Ручной и запланированный поиск проходят одну цепочку.
- Канал указывается для каждого проекта; разные проекты могут использовать
  один канал или разные каналы.
- Одна машина — одно сообщение: фото, краткие характеристики, дата и время
  аукциона, ссылка и оставшееся время до запланированного начала.
- При повторном поиске публикуем только ещё не опубликованные лоты текущего
  раунда в конкретном канале; перенос даты уже опубликованного лота сообщаем
  отдельным уведомлением, исходный пост не редактируем.
- Если запланированное начало уже прошло, сегодняшнюю машину публикуем с
  соответствующей пометкой, без отрицательного обратного отсчёта и без
  неподтверждённого утверждения «торги идут» или «продано».
- Рабочие экраны группируются по сайтам, а не в общем смешанном списке.
  Навигацию и дизайн прорабатываем отдельно до реализации экранов:
  [SOURCE_NAVIGATION_UX_PLAN.md](SOURCE_NAVIGATION_UX_PLAN.md).
- Windows x64 и macOS Apple Silicon имеют одинаковое поведение; UI — RU/UK.

На обсуждении: хранение всей выдачи или только сегодняшних лотов,
срок архива и детали навигации/макетов. Пользователь попросил дополнительно
обдумать хранение; схема ниже остаётся рекомендацией, а не принятым решением.
Предложения ниже не считаются выбранными пользователем до ответа.

## 2. Границы кода и переиспользование

| Уровень | Содержимое |
| --- | --- |
| Общее приложение | Проекты, очередь поиска, отмена, прогресс, записи объявлений, изображения, избранное, история, backup, лицензии, базовый UI |
| Площадки | Представление обычного объявления, полная цена/аренда/лизинг, изменения цены и подтверждение доступности; первоначально поведение Encar |
| Аукционы | Раунды торгов, дата/часовой пояс, точность времени, переносы, лоты на сегодня, архив, общие блоки даты/повреждений/документов |
| Источник | URL, выдача/пагинация, чтение лота, язык, коды полей, правила доступности и собственная композиция карточки/страницы |
| Telegram | Подключение бота, разрешения канала, очередь доставки, шаблон сообщения и журнал отправок; получает нормализованные данные |

Направление зависимостей: модуль сайта использует общие типы, аукционное поведение
использует нормализованные наблюдения, Telegram получает результат подборки.
Ни аукционные правила, ни Telegram не читают селекторы Copart/IAA.

В метаданных источника появляется `family = MARKETPLACE | AUCTION`; семейство
выбирает интерфейс и правила работы. Список возможностей остаётся отдельным:
принадлежность к аукционам не гарантирует наличие ставки, VIN или точного времени.
Не создаём новые сущности «аукционный проект» и «проект площадки» с дублированием
таблицы проектов, пользователей и очереди.

Ориентир структуры, уточняемый при реализации:

```text
backend/app/
  sources/encar/          отдельный алгоритм площадки
  sources/copart/         отдельный алгоритм Copart
  sources/iaai/           отдельный алгоритм IAA
  auctions/              время, раунды, выборка на сегодня, архив
  notifications/         очередь и Telegram-доставка
app/
  shared/                кнопки, иконки, форматирование, общий API
  features/marketplaces/ представление площадок на основе Encar
  features/auctions/     переиспользуемые блоки аукционного интерфейса
  sources/copart/         CopartCarCard, CopartCarPage, локальные стили
  sources/iaai/           IaaCarCard, IaaCarPage, локальные стили
```

Copart получает собственную карточку/страницу на основе копии текущего дизайна.
IAA может использовать те же аукционные блоки, но имеет собственную композицию.
Компоненты Encar не получают аукционные условия и параметры.
Повторно используем действительно совпавшие блоки после изучения обоих сайтов;
не строим заранее универсальный конструктор экранов или иерархию парсеров.
Общие стили проверяются на всех источниках; стили сайта ограничены его модулем.

## 3. Исследование публичных данных до реализации

5 октября поисковые ссылки пользователя не открылись через веб-инструмент.
6 октября выдачи проверены в гостевом браузере: 82 Copart-лота и 74 IAA-лота
(73 US и один CA вне первого объёма). Отдельно проверен сценарий только списков:
повреждения и время начала доступны без открытия карточек. Сведения, точность
времени и оставшиеся ограничения зафиксированы в
[отчёте публичного доступа](MULTISOURCE_PUBLIC_ACCESS_REPORT.md).
Реальный адаптер SearchCar, Windows и разрешённый производственный канал
автоматического доступа пока не подтверждены; MSA-01 остаётся BLOCKED.

Для каждого сайта проверяем один и тот же набор случаев:

1. Точная ссылка пользователя открывается без аккаунта; фильтры сохранились.
2. Полная выдача: страницы/курсор, число результатов, повторы, конец выдачи,
   пустой результат, недоступная страница и блокировка различаются.
3. Лот сегодня, в будущем, без даты, с переносом, недоступный и повторные торги.
4. Доступность даты/пояса, основной фотографии и кратких характеристик без входа.
5. Получение одинаковых результатов из RU/EN интерфейса и после перезапуска.
6. Возможность выбранного канала данных для приложения и публикации сведений/фото.

Результат исследования — таблица полей с доступностью, реальными очищенными
примерами, форматом времени и выбранным способом получения. Если публичных
данных для требуемого сценария недостаточно, отмечаем конкретные недоступные
поля и влияние на продукт; не обещаем обход авторизации или CAPTCHA.

У Copart официальный глоссарий описывает Sale Time как начало аукциона в
местном времени площадки. Справка карточки перечисляет VIN, пробег, повреждения,
документы, характеристики, фотографии и дату торгов, но не подтверждает полноту
всех полей конкретного лота при нашем доступе:
[глоссарий](https://www.copart.com/help/finding-vehicles/glossary-of-common-terms-used-at-copart),
[карточка](https://www.copart.com/help/finding-vehicles/understanding-the-lot-details-page).

IAA предлагает Free Guest для просмотра инвентаря, но наличие такой регистрации
не подтверждает доступность всех полей без аккаунта и не выбирает для нас способ
автоматического доступа: [IAA Registration](https://www.iaai.com/us/Registration/Free).
В исследовании проверяем именно US-сайт из ссылки пользователя.

### Ссылки и язык

Copart-ссылка содержит `searchCriteria` с фильтрами Audi A5, годов 2021–2027,
пробега и типа автомобиля. При нормализации сохраняем смысл вложенных условий,
процентное кодирование и специальные символы. Удаление служебных параметров
допустимо только после проверки, что оно не меняет выдачу.

У IAA из примера условия находятся в непрозрачном `Search?url=…`.
Не считаем этот параметр обычным JSON или придумываем его декодирование;
сохраняем ссылку целиком, проверяем срок действия и зависимость от cookies.
Если она нестабильна, сначала определяем поддерживаемый способ сохранения поиска.

Вместо машинного перевода русской страницы задаём английский язык в собственном
сеансе источника, если сайт это поддерживает; регион остаётся USA.
Предпочитаем структурированные ID/коды и абсолютные даты, когда они доступны.
`Accept-Language` сам по себе не гарантирует язык: проверяем действительную
локаль, штатный переключатель/настройку и сохранение фильтров.

Copart имеет EN/RU версии интерфейса справки:
[English](https://www.copart.com/help/finding-vehicles/understanding-the-lot-details-page),
[Русский](https://www.copart.com/ru/content/us/ru/support/faq-topics/common-terms).
Конкретный механизм переключения поисковых страниц ещё предстоит проверить.
Пользователь может вставлять русские ссылки; SearchCar показывает данные RU/UK
через свои словари независимо от языка чтения сайта. Свободный неизвестный текст
сохраняется в оригинале. Платный переводчик/AI в этот этап не входит.

## 4. Хранение и объём сбора

### Уточнённые правила отбора (06.10.2026)

Пользователь уточнил: исчезнувший лот убираем; без информации об аукционе пока
не добавляем; при начавшемся аукционе нужен соответствующий статус, цена —
если доступна. Эти правила заменяют рекомендации ниже о хранении новых
бездатных лотов и сохранении исчезнувших в активном списке.

- Новые лоты без назначенной даты аукциона не добавляем в проект. При следующем
  поиске выдача читается снова: появление даты позволяет добавить такой лот.
  Дата без точного времени не даёт отсчёт; однозначность локального дня проверяется
  отдельно. `Future`/`Upcoming lot` сами по себе не являются назначенной датой.
- Исчезнувший лот убираем из активного списка проекта после успешного полного
  поиска по тем же условиям. Ошибка/отмена/блокировка или первая страница не
  доказывают исчезновение из всей выдачи. Проверку карточки не требуем.
  Это исключение из подборки, не доказательство продажи.
- Подтверждено: сохраняем датированные будущие лоты, «Сегодня» — отдельная
  локальная выборка. Исчезнувшие исключаются из активного списка с сохранением
  истории, а не физически удаляются. Ключи подтверждённой доставки сохраняются;
  исключение из одного проекта не удаляет запись из другого.
  Детали отображения избранного после исключения пока не согласованы.
- «Аукцион идёт» отображается при явном сигнале источника. Если известно только
  расписание и время наступило, предлагается «Аукцион начался по расписанию»:
  задержки и точный выход машины не подтверждены. Подпись ожидает согласования.
- Если доступна текущая ставка, подписываем её как ставку на момент проверки;
  Buy It Now и оценочную стоимость храним/показываем отдельно. Цена необязательна,
  отсутствие ставки не заменяем нулём. У IAA гостевая ставка пока не подтверждена.

Не решено: что делать, если дата исчезла у уже сохранённого лота;
отображение избранного после исключения; политика неполного поиска перед Telegram.

### Технический вариант только списков

После исследования предложено для первого сценария читать только выдачу,
сохранять краткие сведения всех лотов и вычислять «Сегодня» локально.
Пользователь пока не подтвердил этот вариант; дальнейшее описание чтения
карточек ниже — прежняя рекомендация, не обязательство новой реализации.

В list-only варианте основой служат реально доступные поля строк: ID/ссылка,
название/год, пробег/единица, повреждения, площадка/очередь, расписание с
исходным поясом, отдельные доступные суммы и момент наблюдения. Не обещаем
VIN, вторичные повреждения или остальные детали для каждого источника.
Новые данные не должны обнулять ранее известные поля при их отсутствии.

Исчезновение обрабатывается по уточнённым правилам выше. При неполном поиске
сохраняем данные и показываем охват/давность. Прямую проверку карточки
автоматически не добавляем. Прошедшее начало не подтверждает завершение или
продажу; точный выход машины не выводится из времени начала сессии.

Выбор «только списки» не решает условия автоматического доступа источников.
Браузер может загружать фото-превью сам; отсутствие сохранения файлов в SearchCar
не означает отсутствие загрузки изображений сайтом.

### Прежняя рекомендация для обсуждения

Историческая рекомендация; при конфликте применяются уточнения пользователя
выше. Не реализовывать сохранение новых бездатных лотов или прямую проверку
исчезнувших на основании этого старого варианта.

Предложение: сохранять **все найденные лоты кратко**, а «сегодня» вычислять как
выборку. Отбор только на сегодня уменьшает базу, но теряет будущие даты,
историю переносов и лоты без даты; тогда каждый день потребуется снова искать
их как новые записи. Полную выдачу для обнаружения новых лотов всё равно
проверяем при поиске: хранение не заменяет эту проверку. Поэтому хранение только
сегодняшних лотов — альтернативный режим,
который меняет стратегию поиска, а не только вид списка.

Минимальная запись: источник/ID, ссылка, название/год, дата/пояс/точность,
состояние, площадка, основные доступные характеристики, фото-превью и времена
получения. Сначала используем сведения выдачи, если они надёжны; отсутствие даты
в выдаче может потребовать чтения каждой карточки — ускорение не гарантируем.

Полную карточку и фотографии читаем прежде всего для лотов на сегодня и для
машины, открытой пользователем. Будущие лоты периодически проверяем на дату,
перенос и доступность. Частоту назначаем после замера объёма/лимитов сайтов;
текущий запуск поиска остаётся триггером, отдельные постоянные опросы не добавляем.
Все известные активные лоты проекта, включая ещё не найденные повторно и лоты
без даты, учитываются в проверке расписания; новый охват поиска не превращает
исчезновение в подтверждённую продажу. Избранные лоты обновляются по явной политике.

Предложение жизненного цикла:

| Ситуация | Действие |
| --- | --- |
| Дата в будущем | Активный лот; перепроверяется дата и доступность |
| Сегодня, время ещё впереди | Кандидат в подборку; подробности перед отправкой |
| Дата неизвестна | Отдельная группа «Без даты», без обратного отсчёта |
| Время прошло, результат не прочитан | «Время начала прошло — результат не проверен»; очередная проверка вместо автоматического SOLD |
| Источник подтвердил завершение/отзыв текущих торгов | Раунд закрывается; запись уходит из активной подборки в архив |
| Обнаружены повторные торги | Новый раунд той же записи; возврат в активный список |
| Ошибка/блокировка/отсутствие в ограниченной выдаче | Сохраняем прежние данные и отмечаем недостаток подтверждения |

Исчезновение после полного поиска — основание для проверки прямой ссылки,
а не автоматической продажи/удаления. Архивирование относится к выбранному
проекту/раунду: запись или история, используемая другим проектом, не удаляется.
Архивируемым лотам уменьшаем частоту прямых проверок после подтверждения статуса;
в следующей выдаче всегда распознаём их возврат. Правило Encar «проданные больше
не проверяем» не переносим на аукционы без оценки повторных торгов.

Срок хранения архива (например, 30/90 дней) — отдельное решение. Предлагаем
пока не удалять автоматически записи, избранное, комментарии и историю отправок.
Будущая очистка медиа отличается от очистки метаданных и журнала дедупликации.

| --- | --- |
| Обязательно для идентификации | Источник, внешний ID лота/Stock, внутренний ID, каноническая ссылка, название, время проверки |
| Обязательно для отбора сегодня | Назначенная дата, время/его точность, исходный пояс, UTC при подтверждённом времени, площадка, состояние текущих торгов |
| Краткая карточка/Telegram | Год, марка/модель, фото если доступно, пробег с единицей и достоверностью, основные повреждения, запуск двигателя/ключи если доступны |
| Подробности | Двигатель, топливо, коробка, привод, цвет, документ/штат, дополнительное повреждение, VIN с признаком маскирования |
| Дополнительные суммы | Текущая ставка, Buy It Now, оценочная стоимость с валютой и временем проверки, каждая отдельно и только если доступна |
| Аукционный контекст | Раунд/идентификатор продажи, площадка, lane/run/item, условия подтверждения продавцом, события переноса/завершения |

Нет цены или VIN — не причина отвергать лот. Нет подтверждённой даты/пояса —
причина не публиковать автоматический обратный отсчёт. Неизвестный ключ/запуск/
пробег не трактуется как «нет ключей», «не заводится» или ноль.

Лот и раунд торгов — разные вещи. Идентичность записи `(source, listing_id)`
стабильна, раунд содержит своё расписание и историю наблюдений. Изменение даты
само по себе ещё не доказывает новый раунд: используем исходный sale ID или
подтверждённые переходы состояния. Старые/новые расписания версионируются.

## 6. Время и выборка «сегодня»

- Часовой пояс компьютера определяется в runtime, без фиксации Europe/Warsaw.
  На Windows/macOS получаем идентификатор IANA через проверенную границу shell/UI,
  валидируем backend и учитываем его изменение после сна/смены системных настроек.
- Исходное время и пояс сохраняем; UTC вычисляем только при надёжном разборе.
  Не подставляем пояс компьютера вместо пояса американской площадки.
- День — интервал от локальной полуночи до следующей локальной полуночи,
  преобразованный в UTC; он не всегда равен 24 часам из-за переходов DST.
- Состав подборки рассчитывается по дате **на завершение поиска**. Если поиск
  пересёк полночь, не продолжаем вчерашнюю подборку по времени начала job.
- При дате без точного времени показываем «Время не указано». Включение в
  локальное «сегодня» разрешено лишь если исходная дата/пояс однозначно это
  подтверждают; иначе «Требует уточнения», без выдуманного таймера.
- Если время начала уже прошло, сегодняшнюю машину включаем в публикацию с
  пометкой «Запланированное время начала прошло — результат не проверен».
  Если источник подтвердил состояние, показываем его вместо предположения.
  Прошедшее время само по себе не причина отменять доставку или ставить SOLD.
- Отсчёт рассчитываем при фактической отправке сообщения, не при постановке
  в очередь. Рядом всегда абсолютная дата/время и пояс компьютера: текст
  «через 2 часа» в Telegram устаревает после публикации.

Планируем стандартный `zoneinfo` с пакетом `tzdata` в desktop-сборке: Windows
не гарантирует наличие системной IANA-базы, а одних текущих UTC-смещений
недостаточно для будущих дат. Проверяем упаковку Nuitka и обе ОС:
[Python 3.12 zoneinfo](https://docs.python.org/3.12/library/zoneinfo.html).

## 7. Поиск → подборка → Telegram

1. Запустить выбранные аукционные проекты; каждый через свой адаптер.
2. Сохранить наблюдения и проверить охват. Выдача источников не смешивается.
3. Уточнить дату/доступность и необходимые сведения сегодняшних кандидатов.
4. Завершить поиск и зафиксировать результат. Составить подборку относящихся
   к этому запуску проектов по часовому поясу компьютера.
5. Группировать по подключённому каналу, сортировать по времени начала и убрать
   повтор того же `(source, listing_id, sale_occurrence)` в одном канале.
   Лот, подходящий двум проектам, получает одно сообщение с контекстом проектов.
6. Сохранить задачи доставки и отправить по одному сообщению на машину.
7. В UI отдельно показать итог поиска и «Telegram: отправлено N из M».

Обычное открытие страницы машины не запускает публикацию. Telegram выключен —
поиск и подборка всё равно работают. Повторный поиск не публикует всю прежнюю
подборку: отправляются ещё не доставленные лоты текущих торгов. Явную повторную
отправку делаем отдельным действием, не скрытым эффектом кнопки поиска.

Неполный/отменённый поиск не представляет подборку как полную. По умолчанию
предлагаем не отправлять неполный результат автоматически; показать превью
и причину. При смешанном запуске успешные проекты и ошибочные перечисляются
явно; политику частичной отправки можно согласовать отдельно.

Перед отправкой повторно сверяем локально актуальные дату/статус, свежесть
наблюдения и условия проекта; при устаревании нужна перепроверка источника.
Лот перенесён, отозван, исключён, больше не соответствует проекту или текущий
локальный день сменился — задачу первичной доставки пересматриваем с причиной.
Если начало прошло в ходе доставки, сохраняем сегодняшнюю публикацию и меняем
отсчёт на пометку. Уведомление о переносе ранее опубликованного лота не требует,
чтобы новая дата оставалась сегодняшней: иначе перенос на завтра был бы скрыт.
Доставка не блокирует поисковый worker и не становится частью транзакции поиска.

### Подключение канала

Ссылка на канал не даёт прав отправки. Нужен бот пользователя, его токен и
разрешение администратора «Публикация сообщений». Один локальный бот может
обслуживать несколько каналов/проектов; общего секрета SearchCar в бинарнике нет.

Настройки: подключение Telegram → токен → проверка `getMe` → канал → `getChat`/
`getChatMember` для проверки `can_post_messages` → явная тестовая публикация.
`https://t.me/name` преобразуется в `@name`, после проверки сохраняется стабильный
числовой `chat_id`. Для приватного канала invite-ссылка не эквивалентна chat ID:
предлагаем ввод ID и отдельную инструкцию подключения, не обещаем определить
канал из любой ссылки.

Токен хранится отдельным секретом через Keychain/macOS и DPAPI/Windows,
в исключённой из backup/диагностики зоне. Существующее хранилище лицензии
предназначено для ключа устройства: его 32-байтный формат и имена не используем
для токена. Переиспользуем платформенные механизмы с отдельным именованием
Telegram-секрета; UI после сохранения видит лишь состояние подключения.
В журналах обязательно маскируем токен в URL Bot API и исключаем тело запроса
с секретом. При переносе данных на другую машину подключение требует проверки
и повторного ввода токена; массовая публикация восстановленной очереди выключена.

### Очередь и повторы

Состояния: ожидает / отправляется / отправлено / ошибка / результат неизвестен /
отменено. Для успешной доставки сохраняем `chat_id`, `message_id`, раунд,
версию расписания, время и контекст поискового запуска.

Первичная публикация имеет уникальный ключ `(owner, chat_id, source, listing_id,
sale_occurrence, initial)` — без project ID, чтобы одинаковый лот нескольких
проектов не дублировался в одном канале. Уведомления о переносе дополнительно
включают стабильный ID сохранённого события изменения расписания. Так повторная
проверка одной даты не создаёт уведомление, но следующий настоящий перенос
может создать новое. Смена пояса компьютера меняет отображение, не расписание
источника и не создаёт событие переноса.
Смена даты существующего раунда не создаёт новую первичную публикацию.
Новый подтверждённый раунд может создать её.
Источник и внутренний ID не смешиваются с VIN; межсайтовую склейку не обещаем.

Отправка последовательная в один канал, консервативно не чаще одного сообщения
в секунду; общий лимит бота тоже учитывается. При 429 ждём `retry_after`.
Ошибки прав/токена требуют восстановления настройки, а не бесконечных повторов.
API бесплатен в обычном режиме, платную ускоренную рассылку не включаем:
[Bots FAQ](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this),
[Bot API](https://core.telegram.org/bots/api#responseparameters).

Bot API не предоставляет клиентский idempotency key для `sendMessage`.
Если после отправки оборвалось соединение или процесс завершился до записи
`message_id`, доставка могла состояться. Такую задачу помечаем «результат
неизвестен», не повторяем вслепую; предлагаем проверить канал и повторить явно.
Абсолютную гарантию отсутствия дублей при любой сетевой аварии не обещаем.

Согласованный формат: основное фото (если доступно), проект,
`2022 Audi A5`, источник/номер лота, краткие повреждения/пробег, дата и время
в поясе компьютера, «до начала аукциона осталось 2 ч 15 мин», ссылка.
Поле ставки необязательно и подписано «на момент проверки». Сохраняем
компактный текст в лимите выбранного метода; внешние строки экранируем.
Если фото отсутствует, отправляем текст. Галерею/видео в первую версию не включаем.

После подтверждённого изменения даты/времени уже опубликованного лота отправляем
отдельное уведомление после следующего поиска. Оно содержит источник/номер
лота, прежнюю и новую дату/время и ссылку; исходный пост остаётся неизменным.
Уведомление идёт только в каналы с подтверждённой первичной публикацией данного
раунда; до первичной доставки достаточно обновить саму ожидающую публикацию.
Отдельные уведомления об отмене или снятии лота пока не согласованы.
Автоматическое удаление Telegram-постов не предполагается.

Отправка после поиска не использует отложенные сообщения Telegram. Компьютер
должен быть включён, приложение запущено и иметь сеть; сон/закрытие переносит
обработку очереди. При возобновлении просроченные публикации пересматриваются,
а не отправляются с отрицательным отсчётом: сегодняшние получают пометку,
вчерашние первичные публикации не выдаются за сегодняшние. Сервер не требуется.

## 8. UI/UX

- Основная навигация — рабочие области отдельных сайтов; смешанную страницу
  проектов и общий аукционный экран по умолчанию не создаём. Предложение — сайты
  слева, у выбранного сайта «Проекты», «Запуски», «Настройки». Семейства могут
  служить небольшими подписями групп, но не заменяют разделение по сайтам.
- Создание проекта по поисковой ссылке распознаёт семейство и сайт. Для аукциона
  появляются параметры подборки/Telegram, для площадки — существующие параметры.
- В аукционном проекте: «Все лоты», «Сегодня», «Предстоящие», «Без даты», «Архив».
  «Сегодня» — локальный просмотр сохранённых данных, не утверждение о новом поиске.
- «Сегодня» объединяет проекты только выбранного сайта, с фильтром проекта/
  площадки/времени и видимым поясом компьютера. Общую Copart+IAA подборку в UI
  откладываем. Общий Telegram-канал при этом остаётся допустимым.
- Карточка/страница Copart и IAA имеют заметный блок даты, отсчёт, ссылку на
  лот, повреждения/документы и источник; без обещания точного выхода машины.
- По завершении поиска показываем количество найденных лотов, сегодняшних
  кандидатов и статус отправки. Ошибка Telegram не меняет успешный поиск на ошибку.
- Перед первым включением автоматической отправки — превью сообщения и понятная
  настройка канала. Отправка выключена до подключения/включения пользователем.
- Раздел доставки позволяет увидеть очередь/ошибки/неопределённый результат,
  остановить оставшуюся отправку и явно повторить выбранное сообщение.

Дизайн — отдельный этап U0 с согласованием до UI-реализации:
[план навигации и макетов](SOURCE_NAVIGATION_UX_PLAN.md).
Макеты: боковая панель, рабочая область сайта, создание проекта, аукционная
карточка, страница лота, «Сегодня» и подключение/состояния Telegram. Проверки RU/UK,
узкого окна, клавиатуры, длинных названий и отсутствующих полей.

Сначала тестом фиксируем существенные правила, затем реализуем их: декодирование
URL без потери фильтров, фактический конец выдачи, даты/DST, смена дня/пояса,
дедупликация и состояния доставки. Сетевые fixtures очищаются от секретов.
Отдельно проверяем реальные источники: синтетические данные не доказывают доступ.

Обязательные сценарии: сегодняшняя дата на площадке, но завтра на компьютере;
поиск/доставка через полночь; неизвестное время; смена даты до/после отправки;
повторные торги; одна машина в двух проектах/каналах; сетевой 429/403/timeout;
завершение процесса после отправки до записи результата; ошибка источника;
сон/перезапуск; перенос backup без токена; неизменность Encar.
Дополнительно: начало прошло до/во время доставки; перенос опубликованного лота
на завтра; два последовательных переноса и повторный поиск без изменений;
смена пояса без переноса; переход между сайтами без смены охвата активного job.

Не входит в первую версию: ставки/покупки, live-отслеживание очереди торгов,
точное время выхода лота, серверная отправка при выключенном компьютере,
универсальный перевод свободного текста, межсайтовая склейка по VIN,
массовая автоматическая очистка истории и повторные напоминания до аукциона.

## 10. Вопросы перед реализацией

1. Хранить всю выдачу кратко или только сегодняшние лоты? Дополнительно сравнить
   объём данных и число запросов на реальных выдачах; рекомендация — краткий
   индекс всех лотов и подробности прежде всего для ближайших торгов.
2. Нужен ли срок автоматической очистки архива? Предложение — отложить удаление,
   сначала сделать архив и снижение частоты запросов.
3. Проработать визуальные макеты и детали поведения отдельного этапа дизайна.
   Структура навигации согласована 5 октября; правила первичной публикации,
   переноса и прошедшего начала уже подтверждены. Работа — в отдельной ветке
   `codex/multisource-auctions`.
