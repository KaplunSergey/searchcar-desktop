# Подключение нового источника

11.10.2026. Модули поставляются разработчиками в новой версии SearchCar.
Это не runtime-плагины и не пользовательские исполняемые настройки.
Каталог не ограничен Encar, Copart и IAA; эти сайты — текущие записи.

## Границы

| Часть | Регистрация / ответственность |
| --- | --- |
| Метаданные | `backend/app/sources/catalog.json`: key/name/family/ui/domains/capabilities; один каталог для Python и React |
| Сбор данных | `backend/app/sources/registry.py`: явная factory, версия контракта, модуль сайта |
| Интерфейс | `app/source-modules.tsx`: явная композиция по `ui`, общие props оболочки |
| UI-контракт | `app/source-workspace-contract.ts`: общие данные/действия оболочки, без типов конкретного семейства |
| Detail-ссылка | `app/source-listing-links.ts`: site-specific validator поверх HTTPS, домена, credentials/port checks |
| Общие операции | owner/source-scoped проекты, очередь, отмена, лицензия, preferences; раунды/time API для семейства AUCTION |

Регистрация метаданных, готовность адаптера и право лицензии — разные вещи.
Неподключённый адаптер не попадает в список исполняемых источников;
отсутствующий UI не заменяется Encar/аукционной композицией. Чтение сохранённых
данных и отмена активного запуска не зависят от права начать новый поиск.

## Порядок подключения

1. Проверить prerequisites доступа/способ получения данных и определить
   поля/статусы источника. Для нового live-адаптера нужны fixtures и разрешённый
   smoke; запись в каталоге и mock не доказывают доступность сайта.
2. Добавить metadata: уникальный стабильный `key` (lowercase латиница, цифры,
   дефис; до 32 символов под существующую БД), `name`, `family` = MARKETPLACE
   или AUCTION, `ui`, точные lowercase домены без схемы/пути/порта,
   поддерживаемые capabilities. Порядок внутри семейства определяется каталогом.
   Меню, выбор запуска, маршруты и preferences используют эти данные, не
   требуют изменения фиксированного списка/enum/лимита «3 сайта».
3. Реализовать SourceAdapter в своём модуле и добавить явную factory.
   Descriptor обязан совпадать с каталогом/версией контракта. Алгоритм сайта
   не пишет напрямую в БД и не изменяет другой источник. Поиск проходит через
   существующую общую очередь и повторную проверку прав в POST/worker.
4. Выбрать UI. Для совместимого аукциона `ui: "auction"` использует общий
   AuctionWorkspace/AuctionCard. Для другого дизайна добавить entry-компонент
   в WORKSPACE_MODULES, принимающий SourceWorkspaceProps. Можно обернуть
   AuctionWorkspace и передать свой `listingValidators`, либо зарегистрировать
   site validator в LISTING_VALIDATORS. Общая защита домена остаётся обязательной.
   Площадка получает свою композицию, не автоматический AuctionWorkspace.
5. Валидировать сохранённую ссылку машины по формату/идентичности источника.
   При отсутствии validator ссылка недоступна: search URL не считается detail.
   IAA VehicleDetail ID и stock number различаются — нельзя навязать всем одну
   схему ID. Desktop opener отдельно разрешает HTTPS домены trusted каталога.
6. Добавить RED → GREEN контрактные/интеграционные тесты; пройти регрессии
   Encar, owner/source isolation, ошибки, отмену, права, RU/UK и native packaging.
   JSON уже включается в Nuitka payload и cache fingerprint; проверить наличие
   файла и старт готового sidecar на macOS/Windows перед релизом.

## Реализовано и отложено

Меню/маршруты/launch picker/preferences, auction read/rounds и внешний opener
не ограничены тремя ключами. Это проверено четвёртым аукционом и пятой площадкой
в тестовых fixtures; эти фиктивные сайты **не добавлены** в продуктовый каталог.

Encar пока остаётся прежней композицией внутри `app/page.tsx`: последующее
извлечение в отдельный UI entry должно сохранить его дизайн и тесты. Нельзя
объявлять существующую Encar-страницу универсальным UI для любых площадок.
Новые SourceAdapter всё ещё требуют собственного алгоритма и проверки
совместимости общих контрактов. Универсальные формы специфических параметров,
новые семейства помимо двух согласованных и live Copart/IAA этим срезом не реализованы.

## Необязательное расширение: публичные поисковые пресеты — 17.10.2026

Модуль выбирает стратегию: `capture_search_url`, если публичный адрес хранит
условия (Copart), или `capture_search_request`, если адрес их не хранит (IAA).
URL-only выбор подтверждает валидную загруженную search-ссылку независимо от
необязательных XHR и структуры списка; изменения UI вне URL не сохраняются,
что должно быть явно объяснено пользователю. IAA по-прежнему требует успешного
запроса и готового результата. Полный scan в обоих случаях проверяет реальные
строки и пагинацию, а не использует облегченную readiness выбора.
Также реализуются `validate_selection_snapshot` и при необходимости
`complete_selection_snapshot(snapshot, state)`. Последний вызывается после
завершённого запроса и готовой выдачи; в IAA прикрепляет штатный RequestUri.
Envelope содержит schema_version/source/entry_url/criteria/summary/revision,
creation_url; время `captured_at` заполняет и валидирует модуль (сейчас IAA).
Не сохранять headers, cookies, auth/CAPTCHA state,
весь storage или исполняемые сценарии. Нераспознанные условия отвергать целиком.

`Project.search_config` копируется сервером из закрытого подтверждённого
owner/source-scoped черновика, а не из произвольного клиентского JSON. Общая
очередь фиксирует его вместе с прочими настройками; старые URL jobs совместимы.
Необязательный `search_identity(config)` определяет identity условий источника;
если расширения нет, сохраняется URL identity. Не включать транспортный курсор
в identity IAA и не убирать смысловые фильтры ради совпадения hash.

Для LIST_ONLY collector получает `search_config`. Необязательный
`make_search_guard(page, config)` возвращает source-owned объект с `check()`,
`accept(state, checkpoint)` и `close()`. Он наблюдает обычные запросы, применяет
подтверждённый native/UI путь и проверяет scope перед принятием каждой страницы.
`restore_ready` разрешает подготовку контролов, но **не** чтение неполной
выдачи; прежний full-readiness остаётся обязательным. Все ожидания отменяемые,
действует общий источник-бюджет запросов; guard снимает свои listeners.
Потеря условий — ошибка/partial, без general URL fallback и исключения прежних
машин. Новая конфигурация проекта не меняет уже поставленный запуск и не
разрешает ему исключать лоты относительно более новых условий.
