# Временная диагностика Windows preview

Включается существующим параметром CI `auction_preview=true`
(`SEARCHCAR_SOURCE_TEST_MODE=1` в нативной оболочке). В обычной сборке false:
UI не создаёт таймеров/запросов; нативный поток не стартует; backend отвергает
временные UI/native события с 404. Постоянные source-логи описаны ниже и
не зависят от preview. Настройки лицензии,
поиска, CAPTCHA и отправки Telegram не меняются.

## Следующий тест

1. Установить новую preview-сборку: старый установщик этих инструментов не содержит.
2. Сделать один небольшой поиск Copart. Записать местное время начала/ошибки.
3. На простое: Alt+Space, ждать 45 секунд, Escape, ещё 30 секунд без мыши.
   Отдельно свернуть/развернуть приложение и записать время. Не путать эти случаи.
4. Создать support zip сразу после теста и backup после сбоя; прислать оба.

В `logs.jsonl` появятся:

- `Test diagnostic` с event=native: фокус нативного окна и свёрнутость (`hidden`
  здесь означает именно minimized, не перекрытие другим окном). Проверка каждые
  2 секунды, запись при изменении или раз в 15 секунд. Она выполняется отдельно
  от health-потока, чтобы наблюдение не задерживало проверку backend.
- UI heartbeat каждые 15 секунд, focus/blur/visibility и timer-gap: фактическая
  видимость документа, фокус WebView, задержка таймера, возраст нативного сигнала,
  число ожидающих и ошибочных запросов. Передача не более одной одновременно,
  timeout 3 секунды, без повторов. После закрытия hook удаляет таймер/слушатели.
- menu-key — только Escape/Alt+Space; Windows может перехватить эти клавиши до
  WebView. Отсутствие события НЕ доказывает, что меню не открывали. Это не Win32
  WM_ENTERMENULOOP trace; точные действия тестировщик записывает вручную.
- `Source diagnostic` — постоянные записи Copart/IAA, см. следующий раздел.

UI endpoint требует штатную сессию и CSRF. Native endpoint требует секрет
desktop-сессии; ни один секрет не входит в diagnostic payload. Backend разрешает
только фиксированную схему событий, отбрасывает лишние поля, ограничивает частоту
одним событием каждого типа в секунду. Новые данные идут в обычный ротируемый
журнал и существующий ограниченный/redacted support zip, не на внешний сервер.

Это наблюдение, не исправление Copart или WebView. Временная диагностика
добавляет несколько локальных запросов в минуту. Если UI полностью остановлен,
его события не отправятся — сравнивать с native/health и временем ручных действий.

## Постоянные логи Copart и IAA

`backend/app/source_diagnostics.py` не зависит от временного модуля, UI endpoint
или source_test_mode. Один STARTED и один конечный SUCCESS/код ошибки на чтение
поиска. Нет нового polling, HTTP-запросов к сайту или отправки логов на сервер.

В выгружаемом `logs.jsonl` искать `Source diagnostic:`:

- source, код исхода; случайный attempt связывает начало и конец;
- внутренние scan_id/project_id для сопоставления с историей, без названий;
- выбранный engine, windowed/headless, последний этап, elapsed_ms;
- страницы/ожидаемые страницы, число прочитанных строк и all_pages;
- наблюдаемые ready/blocked/manual/consent/document_loaded, observed;
- последние четыре проблемных ресурса: HTTP-код/тип, роль JS, хеш пути;
- число JS-ошибок (до1000), последние четыре сетевых кода net::ERR_* и HTTP-ошибки
  с типом ресурса и признаком своего сайта. Тексты JS, URL/query, заголовки,
  cookies, секреты, фильтры, названия проектов/машин и HTML не добавляются.

observed=false — DOM недоступен, не доказанное отсутствие CAPTCHA. SUCCESS —
завершён выбранный охват, не обязательно весь каталог. READ_ERROR может означать
отмену или исключение без специального кода: сверить исходный статус в истории.
Сбой логирования не меняет результат поиска. Ограничения уже существующие:
ротация backend-журнала5MiB ×4 файла, экспорт до2MiB за выбранный период,
до10 архивов; manifest указывает диапазон и усечение. Не ждать час до экспорта
после сбоя. Новая проверка подтверждает перенос записи в ZIP и очистку данных.
Это кодовая проверка, не доказательство лога из установленного релизного бинарника.

## Кандидат с автоматическим выбором браузера (после 2fbf2cb)

При создании нового browser session сначала используется установленный HTTPS-браузер
по умолчанию, если это Chrome или Edge. Если стандартный браузер другой,
не определён или его установка отсутствует, приоритет: установленный Chrome,
затем установленный Edge. Учитывается в том числе пользовательская установка.
Если не найден ни один, SOURCE_BROWSER_NOT_INSTALLED просит установить Google
Chrome — при выборе фильтров и при поиске, в RU/UK. Личный профиль не используется.
Явный инженерный `SEARCHCAR_SITE_BROWSER_CHANNEL=chrome|msedge` сохраняет приоритет.
Encar и обычные внешние ссылки этим выбором не изменяются.

В журнал добавлен `Site browser selected: source=... engine=... interactive=...`
без путей/секретов. Фильтры и поиск используют один профиль источника/браузера.
При переходе Edge → Chrome новый профиль SearchCar может запросить проверку
сайта заново; cookies не копируем. Повторный показ уже видимой той же страницы
не перезапускает браузер и не загружает её заново. Для Copart в кандидате от
3 ноября обычный установленный браузер стартует свёрнутым; переход к проверке
восстанавливает ту же страницу без headless → headed перезапуска. Это пробный
режим только изолированного Copart preview. IAA сохраняет прежний fallback;
отсутствие CAPTCHA/403 не гарантируется.

HTTPS-браузер Windows определяется системным `AssocQueryStringW`
(`ASSOCF_IS_PROTOCOL`, `ASSOCSTR_PROGID`), а не только старым UserChoice.
Если API недоступен, read-only fallback проверяет UserChoiceLatest перед UserChoice.
Нативный main-window hook обрабатывает WM_EXITMENULOOP отложенным сообщением:
MoveFocus WebView2 и одно `searchcar:menu-resume`, только когда окно на переднем
плане и не свёрнуто. UI заменяет зависшие активные чтения, не повторяя mutations.
Preview-наблюдение добавляет ограниченное событие `menu-resume` без новых полей.
Отсутствие события не доказывает отсутствие native hook: diagnostic send может
быть занят. Диагностику удалить можно; `windows_menu.rs` и штатный UI recovery
удалять вместе с ней нельзя. Реальный Windows smoke ещё требуется.

Контракты платформы: [HTTPS association](https://learn.microsoft.com/en-us/windows/win32/api/shlwapi/nf-shlwapi-assocquerystringw),
[WM_EXITMENULOOP](https://learn.microsoft.com/en-us/windows/win32/menurc/wm-exitmenuloop).

Проверить на Windows: оба установлены, стандартный Edge → Edge;
стандартный Chrome → Chrome; стандартный Firefox/другой → Chrome, а без Chrome →
Edge. Ни Chrome, ни Edge → просьба установить Chrome без запуска окна и ложного
успеха поиска. Случаи с отсутствующими браузерами проверять на VM, не удалять их
на рабочем ноутбуке. Изменение браузера по умолчанию — только с согласия.
После подтверждения сайта повторить малый поиск тем же браузером/профилем,
сверить журнал и отсутствие лишних перезапусков. Реальный 403/429 не повторять
автоматически. Эта приёмка не закрывается Python mock-тестами на macOS.

Выбор браузера — постоянное поведение, не часть временной телеметрии: при удалении
диагностических hooks не удалять `site_browser_choice.py` и его тесты. Описанный
здесь кандидат ещё требует отдельной сборки; наличие одного 2fbf2cb недостаточно.

## Отключить / удалить перед релизом

Для выключения достаточно `auction_preview=false` (обычный release profile).
Проверки off-mode должны остаться зелёными. Сборка/публикация релиза этим документом
не разрешаются.

Для полного удаления без миграции данных:

1. Удалить `app/test-diagnostics.ts` и его импорт/useEffect в `app/page.tsx`.
2. Удалить `backend/app/test_diagnostics.py`, его router в `main.py`,
   endpoint в `desktop_runtime.py` и его единственную
   запись в PUBLIC_PATHS `http_middleware.py`.
   Оставить `source_diagnostics.py`, его вызовы в `auction_lists.py`, внутренние
   идентификаторы из worker и тесты постоянных source-логов.
3. Удалить `monitor_test_diagnostics` и его вызов/Arc clone из Rust `lib.rs`.
   `monitor_service_health` оставить: это штатная функция приложения.
4. Удалить новые диагностические тесты/hooks и этот документ; повторить backend,
   Node, TypeScript и Rust tests. Не удалять прежние privacy/access проверки.

Улучшения обычного support zip (ограничение повторных успешных опросов,
logs_truncated/диапазон) — не временная телеметрия, их оставляем. Старые backup,
БД и пользовательские проекты не затрагиваются; схема хранения не меняется.
