# SearchCar Desktop: модель угроз для пилота

Дата проверки: 4 сентября 2026 года. Это внутренняя инженерная проверка
архитектуры, а не независимый security-аудит и не гарантия отсутствия уязвимостей.
Она определяет, какие данные защищает пилот, где проходят границы доверия и что
нужно проверить перед расширением пилота.

## Граница продукта

Первый релиз — локальное desktop-приложение для одного клиента на одном активном
устройстве. Рабочая база, изображения, история и резервные копии остаются на
компьютере клиента. Cloudflare хранит только данные лицензий и прав доступа к
источникам; синхронизации рабочих данных и telemetry нет.

Не поддерживаемые угрозы нельзя маскировать под решённые:

- если злоумышленник вошёл в учётную запись ОС клиента или на устройстве есть
  malware с правами этого пользователя, он может прочитать локальные рабочие
  данные;
- SQLite и резервные копии не шифруются сами по себе;
- приложение не заменяет антивирус, резервное копирование ОС или защиту
  пароля пользователя macOS/Windows.

Для пилота это приемлемый остаточный риск: данные изначально предназначены для
локального использования одним владельцем. Для более чувствительных данных
понадобятся шифрование базы/backup и отдельная модель ключей.

## Активы, которые нельзя раскрывать или подменять

| Актив | Где находится | Защита сейчас |
| --- | --- | --- |
| Рабочая SQLite-база, изображения, история | Локальная папка данных приложения | Права текущего пользователя ОС; не входят в support report |
| Лицензионная привязка и private device key | Отдельное системное хранилище устройства | Не попадают в SQLite и переносимые backup; lease подписан Ed25519 |
| Одноразовый секрет local desktop-сессии | Только в окружении sidecar при запуске | Случайный порт на `127.0.0.1`, одноразовый bootstrap, `HttpOnly` + `SameSite=Strict` cookie |
| Коды активации и transfer-коды | Cloudflare D1 | На сервере хранятся только peppered hashes; коды одноразовые |
| Cloudflare signing/pepper/admin secrets | Только Cloudflare secrets / GitHub Actions secrets | Исключены из Git; публичный ключ может быть в конфигурации |
| Ключ подписи updater и подписанные installers | Локально у maintainer и GitHub Actions secret | Клиент проверяет подпись updater; публичный ключ встроен в приложение |
| Support report | Папка, выбранная пользователем | ZIP содержит только `manifest.json` и очищенный `logs.jsonl` |

## Границы доверия и действующие защиты

| Поток | Риск на границе | Защита в реализации |
| --- | --- | --- |
| Tauri shell → local sidecar | Другая локальная страница пытается вызвать API | Sidecar слушает только `127.0.0.1`; shell выделяет случайный порт и передаёт секрет не короче 32 символов. Первое открытие `/desktop/bootstrap` требует этот секрет, затем устанавливает `HttpOnly` session cookie. |
| Local UI → mutation API | CSRF из постороннего окна браузера | Проверка Origin и CSRF-token для операций изменения; разрешённые origins задаются для desktop-порта. |
| Приложение → Cloudflare license Worker | Подмена/повтор ответа или неразрешённый доступ к источнику | HTTPS, подписанные device-запросы, signed lease, лимиты и одноразовые коды; перед началом поиска проверяется entitlement источника. |
| Owner admin → D1 | Несанкционированное изменение лицензии | Owner session, `HttpOnly`/`Secure`/`SameSite=Strict` cookies, пароль с peppered hash, аудит операций. |
| Scanner → Encar | Ненадёжный внешний HTML, CAPTCHA или изменившаяся разметка | Отдельный browser process, явные статусы partial/incomplete, отсутствие автоматического «продано» при неполной странице. |
| UI → системный браузер | Открытие опасного URL | Разрешены только HTTP(S) URLs Encar и Telegram без логина/пароля и без нестандартного порта. |
| Backup restore → local files | Zip Slip, symlink, подмена или zip bomb | Проверка путей, дубликатов, symlink, размера, обязательных файлов и SHA-256 до восстановления; rollback backup. |
| Build/release → публичный release repo | Подмена обновления или утечка исходников | Исходный репозиторий остаётся приватным; публикуются только installer, подпись, checksum и manifest. Updater принимает только подписанные файлы. |
| Logs → support | Секреты/база случайно отправлены в отчёте | Allowlist файлов ZIP, redaction, ограничение размера и retention; база, backup, изображения, license state и cookies исключены. |

## Приоритетные риски и действия

| Приоритет | Сценарий | Текущая защита | Что обязательно сделать/проверить |
| --- | --- | --- | --- |
| Высокий | Компрометация GitHub или Cloudflare token | Секреты не в Git, private source repo | Включить 2FA; ограничить доступ maintainers; fine-grained tokens только нужным репозиторием и `Contents: read/write`; регулярно отзывать неиспользуемые токены. |
| Высокий | Подмена публичного installer/update | Updater signature и checksum | Для каждого релиза сверять подписи обеих платформ и скачивать артефакты до публикации. Позже добавить Apple notarization и Windows signing. |
| Высокий | Потеря/удаление лицензий в D1 | Manual encrypted backup workflow и миграции | Проводить restore drill до расширения пилота и после существенной миграции D1; хранить зашифрованный backup отдельно от рабочего компьютера. |
| Средний | Другой local process пытается использовать API | Loopback + bootstrap secret + cookie/CSRF | Добавить в pilot-check негативный тест: запрос без cookie и с чужим Origin получает `403`; никогда не логировать bootstrap URL/secret. |
| Средний | Внешняя Encar страница или parser даёт неверные данные | Accurate initial scan, partial statuses, технические детали | Вести fixtures для известных страниц и вручную открывать карточку из строки `INCOMPLETE_PAGE` до исправления parser. |
| Средний | Backup/report сохранён в общую папку | Данные контролирует пользователь | В UI и pilot guide ясно предупреждать: backup содержит рабочие данные; support report можно передавать только поддержке. |
| Средний | Support report пропускает новый секрет | Redaction + фиксированный состав ZIP | Перед каждым новым видом логов добавить тест отрицательного случая; сохранять только полезные поля, не сырые request/response. |
| Низкий | Gatekeeper/SmartScreen пугает пользователя | Только updater-подпись, без OS code signing | До коммерческого распространения выполнить фазу 13: Developer ID/notarization и Windows certificate/Trusted Signing. |

## Минимальный security checklist перед каждым пилотным релизом

1. Выполнить release runbook, проверить SHA-256 и updater signatures для macOS
   и Windows артефактов.
2. Убедиться, что GitHub Actions использует secrets только в ручном release
   workflow; не запускать release workflow для непроверенного PR или fork.
3. Проверить, что `.env`, `*.key`, `*.p12`, `*.pfx`, `*.searchcar-backup`,
   SQLite-файлы, build/runtime output не появились в `git status`.
4. На чистом устройстве проверить: trial/activation, отказ источника,
   перенос устройства, backup/restore и проверку обновления.
5. Создать 1-часовой support report и проверить его содержимое: только
   `manifest.json` и `logs.jsonl`; нет кода активации, ключа устройства,
   cookie, локального пути, базы, изображения или комментариев.
6. После изменения D1 schema выполнить удалённую migration, затем проверить
   export и восстановление копии в отдельную test-базу по runbook.

## Операционные правила

- В секретах GitHub и Cloudflare нельзя хранить значения в документации, issue,
  log или chat. При подозрении на раскрытие — отозвать и заменить secret/token,
  затем перевыпустить подписанный клиент, если затронут updater key.
- Не использовать `CODE_PEPPER` как способ исправить один код: его смена делает
  недоступными хеши уже выданных activation-кодов. Менять pepper можно только
  по спланированной процедуре миграции/отзыва.
- Удаление лицензии в owner admin — намеренное отключение клиента. Отключение
  одного source entitlement должно только остановить поиск по этому источнику,
  а не уничтожить license binding.
- В public releases repository не публикуются исходники, backup, логи, ключи,
  D1 export и GitHub Actions artifacts с внутренними путями.
