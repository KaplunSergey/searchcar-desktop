## 1. Подтверждённые границы

Пользователь не хочет объединять все источники в одном рабочем экране.
Группируем по сайтам; дизайн прорабатываем отдельно от разработки алгоритмов.
Структура согласована пользователем 5 октября: слева сайты, у выбранного сайта
открываются проекты, запуски и настройки; общие настройки приложения отдельно.
Визуальные макеты и детали поведения ещё предстоит проработать.

Общее хранение/очередь/компоненты не означают смешанный UI. Семейства «Площадки»
и «Аукционы» определяют поведение модулей, а основной контекст пользователя —
конкретный сайт. Один сайт на проект остаётся неизменным.

Уточнение пользователя 08.10.2026: макет аукционных запусков принят. Для Encar
и будущих источников семейства «Площадки» сохраняем текущий дизайн **проектов
и запусков целиком**, не только карточки машины. Настройки можно пересмотреть
отдельно. Новая навигация по сайтам не разрешает редизайн этих рабочих экранов.
Упрощённый Encar-preview в HTML — обозначение места, не образец для его замены.

## 2. Согласованная структура навигации

Боковая панель с раскрытием только выбранного сайта. Нажатие на название выбирает
сайт и открывает его последнюю страницу, при первом выборе — «Проекты».
У выбранного сайта видны три вложенных пункта. Отдельная кнопка раскрытия не
обязательна: её необходимость проверяем на макете и клавиатурном сценарии.

```text
ПЛОЩАДКИ                  Правая рабочая область
  Encar                   Copart / Проекты

АУКЦИОНЫ                  Проекты | Аукционы сегодня
  Copart                  Только данные Copart
    Проекты
    Запуски
    Настройки
  IAA

Настройки приложения
```

Это схема иерархии, не визуальный макет. Подписи семейств небольшие, без второй
параллельной навигации или отдельного общего экрана «Аукционы». Для узкого окна
предлагаем сворачиваемую панель/меню, но сохраняем видимое название текущего сайта.

- Заголовок/хлебные крошки постоянно обозначают сайт и раздел.
- «Проекты» показывает список выбранного сайта. Создание проекта использует
  этот контекст; ссылка другого сайта вызывает понятное предложение перейти
  к нему, а не молча меняет тип проекта.
- «Запуски» показывает только поиски/результаты выбранного сайта и его машины.
  При общих job из нескольких сайтов отображаем относящуюся к сайту часть,
  сохраняя исходный ID/контекст запуска, а не создавая копии истории.
- «Настройки» — только параметры источника, допустимые по его возможностям.
- У Copart/IAA «Аукционы сегодня» — вкладка внутри «Проектов» либо близкий
  раздел содержания, а не четвёртый пункт боковой панели первой версии.
  Выборка может охватывать несколько проектов одного сайта; фильтр проекта
  доступен. Межсайтовой подборки в UI сейчас нет.
- Избранное, если сохраняется отдельным экраном, тоже имеет явный контекст
  сайта. Его точное место согласуем на макете; не убираем существующие отметки.

Обновление выбранных/всех проектов действует только внутри текущего сайта.
Переход на другой сайт не останавливает поиск или доставку первого. Компактный
индикатор работы/ошибки рядом с названием сайта помогает вернуться к задаче;
не создаём отдельный dashboard с дублирующими сводками.
Кнопка отмены явно указывает свой запуск/проект; смена страницы не меняет цель
уже начатой операции.

Уточнение 08.10.2026 заменяет прежнее исключение межсайтового запуска: нужны
отдельный проект, проекты выбранного сайта и несколько/все сайты. Это области
действия команды, не объединение данных или экранов. Предлагаемый UX:

- существующие «Обновить проекты / Обновить выбранные (N)» остаются на месте
  и относятся только к текущему сайту; один проект также можно запустить отдельно;
- отдельное действие общей оболочки «Обновить данные» открывает выбор сайтов
  с количеством проектов и состоянием доступности; «Все доступные» выбирает
  сайты, но не запускает ничего до подтверждения;
- перед запуском показано, какие проекты будут поставлены в очередь, какие уже
  работают/ожидают и какие пропускаются с причиной. Повторное нажатие не делает
  вторую копию поиска. Для всех недоступных — объяснение, а не пустой «успех»;
- «В очереди» отличается от «Обновление»: возможность поставить другой сайт
  не блокируется работой первого. Для занятого проекта показываем его текущий
  запуск, а не предлагаем повторно начать тот же поиск;
- отмена одного проекта, сайта в общем запуске и всего запуска имеют разные
  явно подписанные цели; переход по навигации ничего не отменяет;
- список запусков каждого сайта содержит только его часть общего запуска.
  Общий идентификатор связывает их, но записи истории не копируются.

Новое общее действие и диалог показаны в макете (§12);
существующие экраны площадок под этот диалог не перестраиваем. Политика
последовательного/параллельного выполнения пока ожидает выбора пользователя;
[механика и ограничения](MULTISOURCE_ARCHITECTURE_PLAN.md#61-области-запуска-и-координация--уточнение-08102026).

## 3. Где находятся настройки

| Область | Содержимое |
| --- | --- |
| Приложение | Язык RU/UK, лицензия, backup/восстановление, обновления, общая скорость поиска/ресурсы устройства, безопасное подключение Telegram-бота |
| Сайт | Поддерживаемые настройки/значения по умолчанию данного источника, его состояние подключения и диагностика; не копии общих настроек |
| Проект | Название, поисковая ссылка/фильтры, охват, расписание поиска, канал и включение публикации Telegram |

Скорость поиска не возвращаем в планировщик и не размножаем по страницам сайтов.
Канал — настройка проекта, токен — секрет подключения приложения. Два сайта могут
доставлять в один канал без смешивания их рабочих экранов. Журнал доставки
показываем в контексте проекта/запуска; общая очередь остаётся внутренней.
Не заполняем настройки сайта пустыми или неподдерживаемыми параметрами.

## 4. Дизайн карточек и страниц

Encar и будущие площадки сохраняют нынешний дизайн проектов и запусков,
карточку/страницу, согласованные действия, фильтры и анимации. Аукционная
история не заменяет историю площадок. Добавление боковой навигации требует
проверки доступной ширины, но не служит поводом переделывать эти экраны.
Настройки площадок можно пересмотреть отдельным макетом с сохранением
поддерживаемых функций и прежних значений.

Уточнение пользователя 07.10.2026: Copart и IAA используют одну общую
аукционную карточку; подробные страницы остаются в границах источников.
Общий визуальный язык — кнопки, типографика, цвета, отступы; общий аукционный
блок — дата/пояс/состояние, если подходит обоим источникам.
Повреждения, документы и характеристики располагаются по значимости для
аукциона. Не добавляем аукционные props/ветки в карточку Encar.

Текущий вариант — [единая карточка v4](mockups/auction-cards-v4.html), заменяет
раздельные карточки v1/v2: без нижнего footer и раскрывающихся деталей.
Состояния и ограничения данных — [исследование](AUCTION_CARD_STATES.md).
v4 добавляет лабораторию состояний и каталог значений из прохода пагинации,
RU/UK и состояния поиска. [Матрица UI](AUCTION_UI_STATE_COVERAGE.md).
Верхние кнопки сайта в лаборатории — переключатель демонстрационных fixtures,
не изменение согласованной левой навигации рабочей области.

Сначала показываем структуру/низкодетальные макеты, после согласования —
визуальные макеты. Не начинаем реализацию всех экранов одновременно.

## 5. Технические границы для реализации после согласования

Один общий layout навигации, реестр источников и контекст `source_key`,
а не три копии приложения. Активная рабочая область определяет сайт для
чтения данных и действий; API проверяет согласованность сайта и проекта.
UI-фильтрации уже полученного общего списка недостаточно.

Маршруты/контекст, ключи запросов и локальные настройки включают сайт и проект
там, где требуется. Выбор, сортировка, раскрытие и раздел запоминаются отдельно
для каждого сайта; черновик формы не теряется при переходе без явного решения.
При запуске восстанавливаем последний доступный сайт/раздел, для мигрированного
пользователя с одним Encar открываем Encar. Отключённый источник отображает
причину и доступ к сохранённым данным согласно правилам лицензии, а не запускает
поиск или переименовывает данные в другой источник.

Стили модулей локальные; изменение общей панели проверяется на всех сайтах.
Общий backend/очередь не меняется только ради раскрытия пунктов навигации.

## 6. Отдельный этап U0

В последовательном [списке задач](MULTISOURCE_IMPLEMENTATION_BACKLOG.md)
дизайн соответствует MSA-03, реализация оболочки — MSA-08, экранов сайтов —
MSA-11/MSA-13. Дизайн принимается отдельно от работающей функции.

1. Иерархия согласована: сайты слева, три подпункта, общие настройки отдельно.
2. Макет оболочки: Encar и Copart, переключение сайта, узкое окно, активный поиск.
3. Макеты Copart: проекты/«Сегодня», карточка, подробности, проект и Telegram.
4. Проверить различия IAA на реальных полях и подготовить его варианты.
5. Макет «Запусков» с поиском/публикациями и раздельными ошибками.
6. После согласования — UI-реализация по одному сайту с регрессией Encar.

Условие готовности: не приходится угадывать текущий сайт; проекты и действия
не смешиваются; смена сайта не прерывает работу; настройки имеют одну понятную
область действия. Проверки Windows/macOS, RU/UK, узкое окно, клавиатура,
длинные названия, loading/error/empty/недоступный источник обязательны.

Открытые решения макета: место избранного, удобство вкладки «Сегодня», поведение
панели в узком окне. Хранение лотов остаётся отдельным продуктовым решением,
не зависит от того, какой список показывается по умолчанию.

## 7. Первый макет v1 — 06.10.2026, для обсуждения

[Открываемый HTML-макет](mockups/auction-workspace-v1.html), без зависимостей,

Ссылки на лоты открывают сайт только при явном нажатии. Расписание, отсчёт и

Подготовлены Copart «Сегодня», Copart «Проекты» и пример карточки IAA.
Сайты и вкладки переключаются ссылками; формы/запуск/сворачивание отключены
и обозначены как макет. Encar не скопирован и не переделан.

- Цвета взяты из `app/globals.css`: navy/blue/ink/line/bg; композиции аукционных
  карточек самостоятельные, без изменения Encar-компонентов.
- Дата/отсчёт важнее ставки; ставка имеет время проверки; оценка IAA показана
  отдельной подписью и не выдаётся за текущую цену покупки.
- «Сегодня» — вкладка в «Проектах» выбранного сайта. Разделы «Запуски» и

- Предложение: избранное — фильтр списка лотов внутри проекта, не новый пункт
  боковой панели; окончательное место ещё не согласовано.

Проверено визуально на macOS в in-app browser, окно 1280×720: Copart «Сегодня»
и «Проекты»; переход в IAA подтверждён accessibility tree. Переключение скрывает

Адаптивные стили есть, но узкое окно/UK/клавиатурный маршрут ещё не проверены.

Следующие варианты: узкое окно, длинные названия/UK, активный поиск с отменой
конкретного запуска, пустое «Сегодня», частичный результат/ошибка, недоступный
источник, прошедшее начало vs подтверждённые торги и сохранённая запись с
пропавшей датой. Спорные правила MSA-02 не считаются принятыми от создания макета.
Полный дизайн и MSA-03 не закрыты; глобальная дизайн-система не реализуется здесь.

## 8. Карточки v2 по референсу пользователя — 07.10.2026

  не гарантия исправности. Неизвестный запуск/ключи — нейтральное «нет данных».

  избранное пока отключено; «Детали автомобиля» раскрывается штатным details.

  показывает вариант неизвестного состояния. Фото заменены заглушками.

через accessibility tree. Viewport возвращён к исходному. UK/Windows и полная
приёмка клавиатуры/малого окна ещё не выполнены. Производственный UI/Encar,

## 14. Аудит рабочих настроек Encar и распределение — 09.10.2026

Статус: предложение по запросу пользователя, не перенос полей и не согласованная
миграция. Источник истины — `app/page.tsx` (ProjectModal/Settings),
`backend/app/schemas.py`, `backend/app/worker.py`, `backend/app/main.py`;
desktop использует тот же Page через `desktop/frontend/main.tsx`.

### Что действительно существует

| Рабочая настройка | Сейчас | Предлагаемое место |
| --- | --- | --- |
| Название и ссылка поиска | Проект | Проект каждого сайта |
| Цена из ссылки / свой диапазон, минимум/максимум KRW | Проект Encar | Только проект Encar; не общий фильтр аукционных ставок |
| Быстрый / точный режим (`scan_mode`) | Проект Encar, новый по умолчанию FAST | Проект Encar; при необходимости дефолт новых проектов в настройках Encar |
| Первая / все страницы (`search_page_mode`) | Проект Encar, по умолчанию все | Проект, если адаптер поддерживает такой охват |
| Ссылка Telegram (`telegram_url`) | Проект, кнопка открывает канал | Проект, сохранив ссылку; не считать подключением бота/разрешением отправки |
| Автообновление (`auto_update`) | Проект | Проект, как единое участие в планировщике |
| Экономный / ускоренный (`performance_mode`) | Общие настройки, хранится рядом с планировщиком | Приложение, отдельно от расписания |
| Включение/пауза планировщика | Общие настройки | Приложение |
| Интервал 1/3/6/12/24 часа | Общий, дефолт 3 часа | Сохранить как общий дефолт; различную частоту сайтов обсудить отдельно |
| Выбор проектов в планировщике | Общие настройки плюс `auto_update` проекта | Один источник истины участия, видимый и в проекте, и в списке планировщика |
| Лицензия, backup/восстановление, данные, диагностика | Общие настройки | Приложение; импорт старого Encar остаётся явно названной операцией данных |
| Язык, проверка обновления приложения | Общая оболочка | Область приложения, без копий в сайтах/проектах |

Текущий `performance_mode` задаёт одну/две параллельно проверяемые карточки Encar;
это не переключатель быстрого/точного алгоритма и не обещание параллельного
исполнения всех сайтов. Будущий общий лимит ресурсов согласуется с MSA-06.
Первый поиск нового Encar-проекта и новый baseline цены принудительно используют
точный режим/все страницы; перенос настроек не отменяет это правило.

Планировщик сейчас берёт пересечение `ScheduledProject` и `Project.auto_update`:
пользователь может включить автообновление в форме, но не выбрать проект в списке.
Предлагаем единое поле участия с двумя представлениями, не два независимых допуска.
Миграция должна сохранить существующий эффективный набор, показать несовпадения
и не начать сканировать ранее исключённые проекты. Догоняющий поиск после сна —
описанная действующая политика, не существующий пользовательский переключатель.

### Три области после перераспределения

- **Приложение:** язык, нагрузка, включение/пауза автообновления, общий интервал,
  Telegram-бот, данные/backup, лицензия, обновления, диагностика. Настройки Telegram
  не блокируют поиск. Язык сообщений можно задать один для бота; отдельные языки
  каждого канала/проекта пока не нужны без такого требования.
- **Сайт:** настоящее состояние подключения/доступа, диагностика конкретного
  адаптера и только поддержанные особенности. Ошибку сети/лицензию показываем
  как статус, не как пользовательский селектор из лаборатории макета. Возможные
  дефолты режима/охвата относятся только к новым проектам, не переписывают старые.
- **Проект:** что искать, охват, специфические фильтры, участие в автообновлении,
  канал и включение публикации там, где она реализована. Проект сохраняет явные
  значения; смена общих дефолтов не должна незаметно менять его поиск.

Рекомендация для частоты: если Copart/IAA требуют другой интервал, добавить в
настройках сайта «Как в приложении / свой интервал», а не сразу расписания каждого
проекта. Тогда Encar сохраняет текущую частоту, а аукционы могут обновляться чаще.
Это новый выбор, не существующая функция; интервалы и политика параллельности
ещё не согласованы. Индивидуальные расписания проекта отложить до реальной
потребности. Эта рекомендация уточняет прежнюю общую фразу «расписание в проекте»:
для первой версии там участие, не самостоятельный таймер.

### Минимальные настройки аукционного проекта

1. Название, поисковая ссылка нужного сайта; сайт фиксирован контекстом создания.
2. Охват: все страницы по умолчанию; ограниченный только при поддержке адаптера,
   с явной пометкой и без вывода об исчезновении за пределами охвата.
3. Участие в автообновлении и понятная подпись эффективного интервала/его источника.
4. Telegram: канал, проверка прав, включение публикации после поиска и превью.
   Подключение бота не дублируется в каждой форме.

Не добавлять быстрый/точный Encar-режим в Copart/IAA при выбранном сборе только
выдачи. Отдельный фильтр «цены автомобиля» не переносить: ставка, Buy It Now,
оценочная стоимость — разные поля; исходные фильтры пока берутся из поисковой ссылки.
Повреждения/пробег/даты — данные или фильтры подборки, не технические настройки сайта.

Подтверждённые правила аукционов не превращаем в множество чекбоксов:
«Сегодня» по поясу компьютера, новые без даты не добавляем, отправляем после
поиска только не опубликованные лоты/раунды в канале, перенос сообщаем отдельно,
прошедшее время само по себе не доказывает live/продажу, исчезновение только по
доказанному полному поиску. Пояс показываем, отдельный ручной выбор не нужен.
Автоматическое удаление архива, детализацию проверок, лимиты/повторы и язык
страницы источника не выносим пользователю как неподтверждённые настройки.

Нужны отдельные решения перед доставкой: формат фото/текст при доступных правах
и данных; автоматическая публикация ограниченного/неполного результата. До выбора
предлагается блокировать такую автоотправку с объяснением, а не заявлять полноту.

### Приёмка последующего переноса

- Encar сохраняет имя/URL/цены/режим/охват и первый baseline; проекты/запуски
  и карточки не редизайнятся из-за новых областей настроек.
- Существующие scheduler-настройки и эффективное участие сохраняются; применение
  нового интервала не запускает внезапно ранее исключённые проекты.
- Смена дефолта новых проектов не меняет старые; сохранение сайта не затрагивает
  настройки другого сайта. На форме видны эффективные режим/охват/интервал.
- Ранее сохранённая Encar-ссылка Telegram не включает автоматически доставку.
  Бот общий, права и канал проверяются отдельно; реальный токен не входит в
  backup/диагностику, замена бота приостанавливает публикацию без потери каналов.
- Ошибка/пауза сайта или Telegram не уничтожает лоты и не блокирует другие
  разрешённые источники. Поиск и доставка имеют независимые результаты.

Дальнейшие изменения поведения выполнять по TDD с characterization-проверками
текущего Encar и миграций, после согласования этого распределения; настоящие
адаптеры/Telegram продолжают иметь отдельные gates в существующем backlog.
