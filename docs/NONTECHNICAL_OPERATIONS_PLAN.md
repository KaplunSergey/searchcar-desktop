# План эксплуатации без технической подготовки

Цель этого документа — заранее определить, какие операции владелец продукта и
клиент должны уметь выполнять без терминала, редактирования конфигураций и
знания программирования.

Финальные инструкции будут дополнены скриншотами после появления работающих
экранов. До завершения соответствующей функции раздел считается требованиями к
реализации, а не готовым руководством.

## Основной принцип

Каждая регулярная операция должна выполняться одним из способов, в порядке
предпочтения:

1. кнопкой или мастером в приложении;
2. кнопкой в лицензионной админке;
3. кнопкой `Run workflow` в GitHub Actions;
4. подписанным скриптом с понятным вопросом и итогом;
5. ручной командой только для первоначальной настройки владельцем.

Ни один клиент не должен устанавливать Python, Node.js, PostgreSQL, Docker,
Playwright или редактировать `.env`.

## Что должно быть автоматизировано в клиентском приложении

### Первый запуск

- проверка системных требований;
- создание каталога данных;
- запуск и проверка backend;
- создание первой SQLite-схемы;
- загрузка или обнаружение включённого Chromium;
- создание ключа устройства;
- показ условий бесплатного периода;
- онлайн-активация 30-дневного trial;
- создание первого локального администратора через форму;
- понятная диагностика при отсутствии интернета или блокировке антивирусом.

### Лицензия

- постоянный индикатор статуса без технических кодов;
- предупреждение за сутки и в последний день;
- форма ввода одноразового ключа;
- кнопка копирования сведений для поддержки;
- кнопка запроса переноса на новое устройство;
- после окончания — безопасный read-only режим с сохранением backup/export.

### Данные

- кнопка `Создать резервную копию`;
- выбор места сохранения стандартным диалогом ОС;
- проверка backup после создания;
- мастер восстановления с предварительным автоматическим backup текущих данных;
- сообщение о совместимости версии;
- запрет восстановления лицензии из backup;
- отчёт о количестве восстановленных пользователей, проектов, авто и файлов.

### Планировщик и фоновая работа

- форма выбора периодичности и проектов;
- понятный переключатель `Автоматические обновления включены`;
- обратный отсчёт до следующего запуска;
- кнопки `Запустить сейчас`, `Приостановить`, `Отменить`;
- после ручного `Обновить проекты` следующий автоматический запуск считается от
  момента завершения: при завершении в 10:27 и интервале 1 час интерфейс сразу
  показывает 11:27, при интервале 3 часа — 13:27;
- ожидающий автоматический запуск не выполняется сразу после ручного повторно;
- обновление отдельного авто не меняет расписание проектов, а при выключенном
  scheduler ручное обновление не включает его автоматически;
- настройка `Запускать приложение вместе с системой`, выключенная по умолчанию;
- настройка `Выполнить один пропущенный запуск после сна/выключения`;
- объяснение, что закрытие окна оставляет scheduler в tray;
- tray-меню `Открыть`, `Следующий запуск`, `Пауза`, `Выйти`;
- предупреждение при полном выходе, что запланированный scan не состоится;
- уведомление о завершении, ошибке, captcha и пропуске из-за лицензии;
- никакого требования держать основное окно открытым.

### Версия и обновление приложения

- версия всегда видна в `Настройки → О приложении` и компактно в sidebar;
- кнопка `Проверить обновления`;
- если GitHub Release новее, появляется `Обновить до vX.Y.Z` и описание;
- при актуальной версии показывается `Установлена последняя версия`;
- после нажатия видны загрузка в процентах, проверка подписи и установка;
- активный scan нельзя оборвать незаметно: предлагается дождаться или отменить;
- scheduler автоматически ставится на паузу на время установки;
- перед обновлением создаётся backup;
- приложение самостоятельно перезапускается и показывает новую версию;
- ошибка проверки/загрузки не блокирует текущую версию и имеет кнопку `Повторить`;
- терминал, ручное скачивание и распаковка для обычного обновления не нужны.

### Диагностика

- экран состояния frontend/backend/browser/database/license service;
- кнопка `Собрать пакет диагностики`;
- удаление из пакета паролей, ключей и персональных комментариев;
- журнал последних запусков и ошибок с понятными русскими пояснениями;
- кнопка открытия каталога данных;
- безопасное восстановление заданий, прерванных закрытием приложения.

## Операции владельца в web-админке

### Создание клиента

1. Нажать `Новый пользователь`.
2. Указать отображаемое имя и контакт.
3. Выбрать `30 дней бесплатно` либо сразу платный срок.
4. Нажать `Создать`.
5. Скопировать короткую инструкцию клиенту.

### Выпуск продления

1. Открыть пользователя.
2. Нажать `Создать ключ продления`.
3. Выбрать 1, 3, 6, 12 месяцев или бессрочно.
4. Проверить предварительно рассчитанную новую дату.
5. Скопировать одноразовый ключ.

Админка должна явно показывать, использован ли ключ, когда и на какой лицензии.

### Перенос устройства

1. Клиент присылает одноразовый код нового устройства.
2. Владелец открывает лицензию и нажимает `Перенести устройство`.
3. Вводит код или вставляет его из буфера.
4. Сравнивает пользователя, старое и новое устройство, срок и историю.
5. Подтверждает действие повторной кнопкой.
6. Получает итог `Перенос завершён` и готовый текст ответа клиенту.

Действие должно быть атомарным: при ошибке старая привязка остаётся рабочей.

### Резервная копия лицензионного сервера

- кнопка или GitHub workflow `Backup license service`;
- экспорт D1 в зашифрованный архив владельца;
- отдельная проверка наличия offline-копии signing key;
- автоматическое указание даты последнего успешного backup;
- ежемесячное напоминание владельцу.

## Бесплатная первоначальная настройка инфраструктуры

Потребуются только аккаунты Cloudflare и GitHub. Собственный домен и платный
Cloudflare-тариф не обязательны.

Должен быть подготовлен мастер `scripts/setup-cloudflare` для macOS и Windows,
который:

1. проверяет наличие необходимых инструментов или запускается через GitHub
   Actions без локальной установки;
2. открывает авторизацию Cloudflare в браузере;
3. создаёт D1-базу;
4. применяет миграции;
5. публикует Worker и админку;
6. просит владельца создать пароль администратора;
7. создаёт и сохраняет секрет подписи вне репозитория;
8. выполняет тестовую активацию;
9. формирует PDF/Markdown с адресами и инструкциями восстановления.

То, что нельзя автоматизировать из-за правил сервиса, оформляется отдельными
экранами `Шаг 1 из N` с точными названиями кнопок.

## Бесплатный выпуск новой версии

Планируемый сценарий для владельца:

1. Открыть вкладку `Actions` приватного source-репозитория.
2. Выбрать `Build desktop release`.
3. Нажать `Run workflow` и ввести номер версии и краткое описание.
4. Дождаться зелёного результата Windows и macOS.
5. Скачать тестовые установщики и пройти короткий smoke-checklist.
6. Нажать `Approve publication`.
7. Workflow публикует подписанные Tauri artifacts в releases-only репозитории.
8. Только после успешной загрузки всех платформ публикует `latest.json`, чтобы
   клиенты никогда не увидели неполный релиз.

Если бесплатных CI-минут недостаточно, должны существовать два локальных
скрипта: `build-windows.ps1` и `build-macos.sh`. Они проверяют окружение,
собирают пакет и не требуют знания внутренних команд.

## Установка бесплатной пилотной версии

### Windows 10/11

Инструкция должна содержать скриншоты SmartScreen и последовательность
`Подробнее` → `Выполнить в любом случае`. Для Windows 11 отдельно проверяется
Smart App Control; если корпоративная политика запрещает запуск, инструкция не
предлагает ослаблять защиту и сообщает, что потребуется подписанная сборка.

### macOS 13+ Apple Silicon

Приложение получает ad-hoc подпись. Инструкция показывает первый запуск,
`System Settings` → `Privacy & Security` → `Open Anyway` и повторное
подтверждение. На управляемом корпоративном Mac возможность обхода может быть
отключена.

Перед коммерческой поставкой планируется Developer ID/notarization для macOS и
доверенная подпись Windows. Это отдельный платный этап и не блокирует пилот.

## Аварийные сценарии

Для каждого сценария будет отдельная страница с признаками, решением и точкой,
после которой нужна техническая помощь:

- Cloudflare временно недоступен;
- пользователь пропустил ежедневную проверку;
- signing key потерян или скомпрометирован;
- D1 случайно очищена;
- GitHub Releases недоступен;
- установщик заблокирован ОС или антивирусом;
- старый компьютер сломан;
- backup повреждён;
- приложение закрылось во время поиска;
- scheduler не запустился после сна/перезапуска;
- scheduler создал повторный запуск;
- обновление не найдено при наличии нового stable release;
- загрузка обновления прервалась;
- подпись обновления не прошла проверку;
- новая версия не запускается;
- Encar показывает captcha или ограничивает запросы.
